## PMP (object placement), decoded
- Header: "PMPF"; u16 object count @0x10; u32 table offset @0x40 (always 0x80); file size equals 0x80 + count*0x58 in all 14 files.
- Record (0x58 bytes): u16 @0 = 1; u16 @2 = object type id; u8 @4 = variant flag; f32 x,y,z @0x08; f32 scale x,y,z @0x14; 3x3 matrix as three 3-float vectors @0x20, @0x2C, @0x38; s32 @0x44 = -1 (no parent in all 1361 records); u16 x4 @0x48 unknown.
- Loader check: the record stride 0x58 and count at 0x10 match the decompiled loop in `src/core/decompiled/decompiled.c` (FUN_801bf564 / FUN_801bf5e4, RPUtlMapData.cpp).
- Validation: positions lie inside the stage KCL vertex bounding box (+50 margin) for 1,321 of 1,361 objects. Misses: glf_course_angle 24 of 50, fc3 9, fc1 2, and one each in fc11, fc13, fc8, fc9, survey. Survey has 2 objects and an all-zero KCL box (not useful).
- Object ids seen: 0,1,2,3,4,5,8,10,17,19 (most common 2 and 3). No object names are stored in the file, so ids are unresolved.
- Rotation: all 1361 matrices are orthonormal but have det = -1 (improper). Either the stored rows use a mirrored convention or a fixed axis flip is applied at runtime. Not resolved; treat rotation as "axes as stored".
- variant flag: 75 records have flag 1, all in glf_course_fc11 (42) and glf_course_fc3 (33); the loader keeps flag-0 records or those matching the scene variant.
- Confidence: high for layout and positions; medium for scale; low for rotation meaning and type ids.

## Other formats
- PLIGHT: "LGHT" + size (1352 in all samples). 0x48-byte header, then 16 LOBJ slots of 0x50 bytes (72 + 16*80 = 1352). Header RGBA colours (e.g. a0a0a0ff, 4a371aff, 646464ff). Slot fields not decoded beyond a 3-float block that looks like a position/direction.
- PLMAP: "LMAP" + size (408 in glf_scene_fc1). LTEX block (0xBC) names `lm_0` (boxing and fc8 also list `lm_1`). Those names resolve to `src/core/shared/SportsStatic/common/common.carc/lm_0.bti` and `lm_1.bti` (RGBA8, 32x32).
- PBLM: "PBLM" + size (164). Floats: 0.1 in golf files, 0.4 in tennis scene_Bloom. Other fields unknown.
- PMMISC: "MMSC" + size (420 in golf). Names like `M_Bunker_v`, `M_Green_v`, `M_Rough_v`, `M_Sky_v`, `M_Fairway_v`, `M_map_tree1_v(n)`. Names are often split by stray bytes, so extraction is regex-based; entry layout not verified. Several names match golf course material names (`M_Bunker`, `M_Green`, ...) or `glf_sky.brres`.
- BTI: GX format byte @0 (0=I4, 4=RGB565, 5=RGB5A3, 6=RGBA8, 2=IA4 ...), width/height u16 @2/@4, mip count @0x18, data offset @0x1C (= 0x20). File sizes match header-derived sizes for all 10.
- RCD: 74 bytes; the size and name field fit the Wii Mii character-data layout. Names decode to Japanese nicknames (e.g. cpu_mii_000 = "さぶろう"). The rest of the record is not decoded.
- BMG: "MESG" "bmg1", section count 3: INF1, DAT1, MID1.
- BIN: not decoded (u32/float tables, plus a "BWCH" header with a build date in TrialData.bin).

## Scene composition (26 stage/environment folders)
- Golf courses (14 `assets/maps/golf/glf_course_*.carc`): each has `G3D/glf_course_X.brres` (1 model, `glf_course_X.glb`) and `G3D/glf_map_X.brres` (`glf_map_X__glf_map_X.glb`, `glf_map_X__glf_tree_X.glb`), `glf_course_X.kcl`, `glf_course_X.pmp`, and `glf_scene_X/` with .plight, .plmap, .pblm. Example: glf_course_fc1 = 3 GLB, 1 KCL, 119 objects, 1 lightset.
- Tennis (`tns_Field_a/b.carc`): brres + KCL, no PMP or light files in the stage folder; tennis lighting lives in `src/minigames/tennis/common/common.carc/Environment/`.
- Boxing (`MainGame.carc`): 26 GLB, no KCL or PMP; lights in EnvMain/ and EnvMiniGame/ (plight/plmap/pblm).
- Baseball `ballpark00.carc`: 3 GLB only.
- Shared environments (`src/minigames/*/common/common.carc/Environment`): plight/plmap/pblm and pmmisc (golf, bowling, baseball). The golf one also has `M_*` names matching course materials.
- Full per-stage lists (model GLB paths, KCL, PMP, lighting, other) are in `maps.json` under `stages`.

## References
- plmap -> lm_0.bti / lm_1.bti: resolved for all 19 files.
- pmmisc -> golf brres materials/bones: partly resolved (M_Bunker_v, M_Green_v, M_Rough_v, M_Fairway_v, M_Sky_v). `M_Kiwa_v`, `M_XNamiuchi_v_x`, `M_map_tree1_v` do not resolve to any brres in the project (names left null).
- pmp, plight, pblm, bti, bmg, rcd: no outward name references found. PMP object ids are not names.

## Caveats
- Confidence is medium or lower for everything except PMP layout, BTI and the non-game file classification.
- PMP type ids and rotation semantics are unverified. Do not place objects by type name.
- .map/.cts/.mts files are not linker maps or game data; nothing to convert.
